# Supabase

Postgres + Auth + REST for nomai. The repo is linked to a hosted project via
the Supabase CLI; schema lives in `supabase/migrations/` and seed data in
`supabase/seed.sql`.

## Docs in this folder

- **`setup.md`** — per-app `.env` files: which variables, where to get them,
  what is safe to share. Start here on a fresh clone.
- **`schema.md`** — tables, columns and RLS policies, mapped to domain terms
  (`GLOSSARY.md`) and the ADRs that shaped them.
- **`clients.md`** — how to query Supabase from `apps/web` (browser, server,
  middleware) and `apps/api` (admin client).
- **`cli.md`** — everyday CLI workflows: migrations, seeds, type generation,
  ad-hoc queries.

## Layout

```
supabase/
├── config.toml            # CLI project config (generated by supabase init)
├── migrations/            # applied with `supabase db push`
│   ├── …_init.sql         # travelers, agent_wallets, bookings v1 + RLS
│   └── …                  # publications model, escrow/Service fee,
│                          # agent_usage, currencies — see schema.md
├── seed.sql               # marketplace inventory, generated — see cli.md
└── .temp/                 # CLI state (gitignored)
```

## Invariants worth knowing

- **The platform never holds booking funds** (ADR-0001/0006): a Booking's
  `pay_to` is the escrow contract; the Owner's `payout_address` receives the
  staged releases (50% at the Cancellation deadline, the rest 24 h after
  check-in). `payments` rows are the settlement receipts around that escrow.
- **Agent usage is metered, not a balance** (ADR-0002/0005): `agent_usage`
  rows record `cost_units` per `stage`; the daily free-tier caps are
  enforced in `apps/api` (`src/usage.ts`). There is no balance column and
  nothing to top up — the agent wallet's on-chain balance is the hard cap.
- **The browser only ever holds the publishable key.** The secret key lives
  in `apps/api` only and bypasses RLS — see `setup.md` for the rules.
